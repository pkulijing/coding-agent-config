# review 角度清单

`/review-loop` 编队里每个 reviewer 审一个角度。本文件每一节都是**可原文转发**的清单：orchestrator 把对应那一节**逐字**交给该 reviewer，不改写、不压缩、不合并。

**为什么必须是清单、必须原文转发**：reviewer 跑在 `medium` 思考档上。显式清单使 reviewer 能逐项检查；降低思考档时更需要完整的任务范围。模型可能会**把工作范围收敛到被明确要求的事**上，清单在，它逐项去看；清单被压成一句话，它就自行决定看什么，降档立刻变成降检出。清单是降档的**配套条件**，不是可选的润色。

**默认档**用 ①②③，**重档**用 ①②③④⑤（⑤ 交给 `code-reviewer-deep`）。

---

## ① 契约与装配

> 这是 AI 写 / 改的代码**最常出错的地方**：一个组件的输出成为另一个组件的输入时。改了返回形状，单测不红，调用方炸。优先级排第一不是习惯，是失败分布决定的。

1. diff 改过的每个函数 / 方法 / 接口，找出**全部调用点**，逐个核对：参数个数与顺序、类型、可空性、默认值，是否仍然匹配。
2. diff 改过的**返回值结构**（字段名、嵌套层级、类型、是否可能为空 / None），逐个核对消费方是否仍能正确解析。
3. 跨文件的常量 / 枚举 / 配置键 / 事件名 / 路由字符串 / 环境变量名：一端改了，另一端跟着改了吗。
4. diff 新增或改名的符号：有没有遗漏的引用点 —— 包括**字符串形式的引用**、文档里写的路径、脚本里的调用。
5. 接壤代码：紧邻改动的上下文（同函数的其余部分、同类的其他方法）是否被这次改动破坏了原有前提。
6. 若 diff 自称「只是重构 / 等价替换」，**逐条验证等价性**。不等价的重构是最难发现的一类回归。

## ② 缺陷定向扫描

**先看这几类文件，顺序不能反**：CI / workflow 配置、权限与认证 / CORS、部署目标、依赖版本与锁文件、构建与运行时开关。它们在 diff 里往往不起眼，但一行就可能改变安全态或线上行为。

然后按高频失败形态过一遍改动的代码：

1. **不存在的包 / API / 参数**：import 的包真的在依赖清单里吗；调用的方法名与参数名真的存在于该版本吗。（AI 生成代码的包幻觉率约 19.6%，且被 slopsquatting 武器化。）
2. **错误处理**：新增的失败路径处理了吗；有没有 catch 了却吞掉；错误信息会不会泄露敏感值。
3. **边界与空值**：空集合、None / null、0、负数、超长输入、首尾元素。
4. **资源开关配对**：open/close、acquire/release、begin/commit、订阅/退订 —— 在**异常路径**上也配对吗。
5. **重复实现**：新写的工具函数，仓库里是不是已经有一个。
6. **硬编码**：路径、地址、端口、凭据、魔数。

## ③ 项目规范合规

1. 读项目 `AGENTS.md`（仅旧项目缺失时读 `CLAUDE.md`）与全局规范，逐条核对本次 diff 是否违反。
2. 命中触发条件的 `playbooks/*.md`，**读了再判**，不要凭印象 —— 你对某条规则的记忆可能来自别的项目或别的版本。
3. **写码指引不全适用于 review**：规范里「新代码应该怎么写」的条目，不构成「已有代码必须改」的 finding。
4. 只报**违反了明确写下来的规则**的项，并附规则出处（文件 + 原文）。凭个人品味的一律不报。

## ④ git 历史上下文（重档）

1. 对被改动的区域跑 `git log` / `git blame`，看近期变更史。
2. 这次改动是否**撤销了**某个之前为修 bug 而加的东西 —— 最典型的回归形态：看起来是「清理冗余」，实则删掉了一个 fix。
3. 同一区域最近是否被反复改动。反复改动的地方通常有未被理解的约束。
4. 本次 diff 是否与近期某次改动的**意图**冲突（不是文本冲突，是设计意图冲突）。

## ⑤ 并发 / 状态机 / 资源生命周期（重档，`code-reviewer-deep`）

> 这一维是同模型自审盲区最大的地方，也是测试复现不出来、只能靠推演的地方。**一条 finding = 一条可复述的执行序列。**

1. **共享状态**：哪些数据被多个线程 / 任务读写；锁的保护范围覆盖了全部读写路径吗。
2. **顺序假设**：代码是否假定了 A 先于 B，而调度并不保证。
3. **生命周期**：创建 / 启动 / 取消 / join / 优雅停，每条路径都走一遍。特别是「取消发生在启动完成之前」和「停在中途」。
4. **重入与陈旧状态**：回调 / 事件处理可能重入吗；读到的状态可能已经过期吗。
5. **异常路径上的资源**：抛异常时锁释放了吗、任务取消了吗、连接关了吗。
6. **跨进程 / 网络**：重试是否幂等；部分失败怎么回滚；超时与降级路径可达吗。
