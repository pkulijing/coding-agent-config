# review-loop 的设计推导

> 本文是 `skills/review-loop/SKILL.md` 的**推导层**：规则本身留在 SKILL.md，这里只记「为什么长这样」，每条都来自实际翻过的车。
>
> **何时读（硬触发）**：
>
> - **要改 SKILL.md 的收敛判据 / 档位表 / 降级链门槛 / 「明确不做」清单之前**——不读就改，等于把防线连同它的来历一起改掉；
> - Step 4 委派时对「为什么必须把仓库根传给整个编队、为什么必须 `git -C` 而不是让它 `cd`」有疑问时；
> - 6.4 对「为什么 2 轮不收敛是留痕放行而非停下问人」有疑问时。
>
> 日常跑一轮 loop 不必读本文。

## 1. 病根（决定了 loop 的形状，每条都来自实际翻过的车）

- **无运行验证 → 基础功能被审废无人知**。reviewer 只读代码、不跑代码；若收敛只看「reviewer 说没问题」，某轮「外科手术式修复」把主流程改废了也没人发现。故运行验证是硬前置，**排在 reviewer 意见之前**。
- **无置信过滤 → 无限挑刺**。reviewer（尤其对规则类文档）的问题空间近乎无穷，任何编得出的 corner case 都算「可能出错」。故只认高置信、有证据的 correctness finding。
- **成本与 diff 规模脱钩 → 一次 review 烧光 session 预算**。故编队规格与 diff 复杂度挂钩，且永远在子 agent 里跑。
- **思考档跟着主会话继承 → 花深思考的钱，买注定被丢弃的东西**。主会话在 `xhigh` 时整个编队跟着 `xhigh` 跑（实测单轮 10–25 分钟、13–23 万 token），而真正阻断的 finding 全部来自**多角度独立 + 契约追踪 + 探针验证**，深想只额外产出一批被置信闸滤掉的钻牛角尖项 —— 延长推理甚至会让模型放弃原本正确的答案。故 **model 与思考档由端对应的 `agents/*.md` 或 `agents/codex-review.toml` 钉死，不继承主会话**。

## 2. 为什么不依赖 CC 内置 `/code-review`

新版 CC 给它加了 `disable-model-invocation`，任何模型上下文都调不动，且该 flag 随版本漂移、不可观测（同一台机器数周内从可用变为不可用）。主路径不能押在不可控的外部假设上，故 review 方法论由本 skill 自持（多角度并行 + 置信 rubric 正是其方法论的移植，rubric 与其官方实现对齐）。人工仍可自己手输 `/code-review`。

## 3. 已知局限：同模型自审

reviewer 与实现方可能属于同一模型家族，存在**同模型自审**风险，对并发 / 多线程 / 难复现改动有已知盲区。硬实证：一处 grpc.aio 消费迁专用线程的重构，CC 自审只发现 2 个并发隐患，换独立模型（codex）又补出 3 个 P1，其中「优雅停不可达」CC 完全漏判。**本 skill 不自动引入跨模型第二意见**（判定链长、触发率近零、维护面外溢），需要时人工手动引入。独立的是 **context** 而非模型 —— 升重档只是缓解，不等于消除。

## 4. 为什么只有两档、且不再往下调思考档

真正琐碎的已在 Step 2 跳过；没跳过的（配置、指令规则文件）每行都重。**角度数是检出率的主驱动，不能砍**；而 `medium` 已是 Sonnet 编码场景的底 —— 官方分模型建议里 `low` 明确只适用于 chat 等非编码场景，再降一档省下的钱要拿编码判断力去付。且本 loop 的成本大头是**误报引发的无效修复轮**，压误报靠置信闸与探针验证，不靠减 reviewer。

同理，「编队只有两档、不自行加码」也不是省钱条款：要调编队规格就改 `agents/*.md`（那是单一真源），临时在委派时加码会让「档位表说了算」这个前提失效。

## 5. Step 4 · 为什么必须把仓库根传给整个编队

**为什么要传**：子 agent 继承的是**会话的主工作目录**（主 checkout），继承不到主会话 shell `cd` 进 worktree 后的 cwd。而 `/start` 默认每轮在独立 worktree 里开发 —— 不把根传下去，reviewer 就会在主 checkout 上跑 `git diff`，读到的是**另一个分支的改动**（那里常躺着别轮的未提交文件），认认真真审完报 clean。**失败完全静默**，没有任何一步会发现审错了对象。

**为什么必须是 `-C` 而不是让它 `cd` 过去**：主会话的 shell 状态跨调用保持，**agent 线程的不保持** —— 实测（`cd /tmp && pwd` 得 `/tmp`，下一次独立调用 `pwd` 弹回原目录）与环境说明「Agent threads always have their cwd reset between bash calls」一致。允许 `cd` 等于把同一个静默失败换个更隐蔽的形态放回来：自证做了、`cd` 也成功了一次，后续每条命令又飘回错的树。

## 6. 为什么 2 轮不收敛是留痕放行而非停下问人

「哪些边际问题值得修」终究是人的判断（规则类文档的问题空间近乎无穷，置信闸已压掉大半，但边际取舍仍在）；而「停下问人」会让后台 / 云端会话永久挂起、也让人为等 loop 干坐。把这个判断连同证据前移到 `/finish`，与「人工 review 前移」的总架构一致。
