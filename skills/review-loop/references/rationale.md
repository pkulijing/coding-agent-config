# review-loop 的设计边界

修改收敛判据、编队、降级门槛或“明确不做”清单前读本文；日常 review 无需加载。执行规则以 SKILL.md 为准，历史事故在 Git 与既有开发记录中，不在这里重建档案。

## 1. 运行验证与置信过滤

运行验证检查改动是否仍能完成基础行为；独立 review 检查代码、契约和边界。二者不可互替。只采纳有证据的高置信正确性问题，避免可无限延伸的风格讨论驱动修复。

## 2. 自持 review 流程

自动路径使用本技能和原生子 agent，不依赖 CC 内置 `/code-review` 的可调用性。人工仍可使用该入口；它不替代本流程的基线与结果契约。

## 3. 独立 context 的局限

独立 context 不等于不同模型家族，不保证消除共同盲区。自动流程不新增跨模型第二意见；需要改变这一交付方式时由用户决定。

## 4. 两档编队

人数、角度与模型/思考档是既定工作方式，不能在调用时临时减配或加码。规格由 SKILL.md 档位表及两端角色配置共同定义。修改它们须作为明确的流程决策，不借删叙事改变审查覆盖。

## 5. 工作树身份

所有委派都传绝对仓库根，子 agent 自证根并显式指定操作路径，避免审查落在另一个 checkout。工具是否保持 cwd 不作为流程前提。

## 6. 两轮留痕放行

修复轮上限控制反复审查成本；未收敛结果和降级证据进入 REVIEW、提交消息与交付说明，把剩余取舍交给收尾审阅。它不授权隐藏失败，也不替代调用方规定的运行验证门槛。
