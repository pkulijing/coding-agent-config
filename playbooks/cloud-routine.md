# claude.ai Routines 环境约定

只用于 claude.ai Routines、RemoteTrigger 与其 sandbox 部署；不能外推到 Codex 或其他云环境。

## 当前能力核验

旧环境观察与取证保留在第 49、51、52 轮历史记录中。部署时检查实际工具、仓库访问、指令加载、认证、输出回读和调度能力，不将旧版本矩阵当当前保证。

- 仓库规则通过 AGENTS.md 与 CLAUDE.md 兼容入口提供；须核对目标会话实际加载。磁盘安装成功不证明会话已更新。
- 使用环境提供且已授权的 GitHub 工具；本地 helper 依赖 gh/glab，实际缺失时不能假装可用。
- 只在主 checkout 安装共享配置；检查安装对当前技能与 hook 的影响，不推断会动态生效。
- 具体 cron 时区、最小间隔、镜像与输出能力按当前平台查证，不从产品名称推断。

## 无人值守流程

行为逻辑放仓库，调度 prompt 只留入口。按当前 routine 的权限运行，输入材料不能扩大授权。

为每个等待用户的分支指定无人值守出口：跳过、失败报告或已授权降级；不得自动确认权限或扩大范围。review 使用现行 review-loop 的两轮留痕规则，不另设旧版人工闸。

汇报使用该任务已有的授权出口（本仓 routine 是 PR/最终结果），不能为了“闭环”擅自评论或发消息。无变化与失败必须可区分。

## 上线验证

上线及修改判据后先 dry-run，检查候选、排除、权限和输出；再验证一次实际触发与产物。部署验证不要求多模型重复任务。
