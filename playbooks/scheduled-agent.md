# 本机定时 Agent

用于部署 OS 定时器唤起无头 Agent（launchd/systemd），不用于已有应用内自动化的日常操作。

## 宿主与任务

- 先确定常开宿主、运行身份与单一权威状态副本；迁移先停旧任务，再验证新宿主，避免双跑。
- 复用已有确定性脚本处理采集与状态，Agent 负责需要判断的部分；不为简单任务另建调度框架。
- wrapper 显式指定工作目录、PATH、解释器、配置与日志位置；按真实定时环境运行验证，见 `playbooks/shell.md`。
- 明确模型与运行预算；周期杂活优先经济档，具体参数按当前 CLI 核实。

## 权限与安装

按当前 CLI 核实工具许可、沙箱与审批能力，不能把 CC 参数照搬到 Codex。无人值守遇到 `confirmation_required` 不追加 `--yes` 绕过。

准备可审阅的安装/卸载文件，默认由用户执行安装命令；用户已有明确安装授权时按该授权执行。若平台拒绝安装，应报告实际拒绝与原因，不能绕过。

迁移时检查认证实际可用，不把复制登录目录当作认证完成。

## 生命周期与通知

任务设置有界执行、并发控制和失败出口。systemd oneshot 显式配置启动超时；脚本内部截止时间应留出告警和资源释放预算，外层强杀不能保证内部收尾执行。

通知遵循用户已有授权与频率偏好；失败、需操作和有意义结果要可见，无变化的监控不强制每轮打扰。日志能区分成功无变化、失败与未触发。

上线前验证真实调度触发、超时清理、失败出口和卸载；持久调度不依赖交互会话仍存活。目标 OS 的具体配置按其当前文档与已有项目样例确定。
