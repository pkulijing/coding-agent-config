# Shell 脚本开发规则

用于 shell 脚本、远程命令及需要用户粘贴执行的命令。具体解释器以 shebang 和目标环境为准。

## 1. 引号与生成文本

- 长远程命令放脚本，不嵌套拼接多层引号；数据作为参数传递，不作为代码插入。
- heredoc 默认给分隔符加引号；确需展开时检查正文和注释中的变量与命令替换。字符串内的 `#` 不提供 shell 注释保护。
- 中文或其他字符紧贴变量时使用 `${var}` 明确边界。
- 给用户的多步或长命令写入短路径脚本，只提供一条短执行命令。

## 2. 执行环境

ssh、CI、定时器不保证与交互终端相同。显式指定工作目录、解释器、必要 PATH 和环境；按真实非交互入口验证，不依据手工登录成功推断。shell 启动文件行为取决于 shell 与调用方式，不一概断言 ssh 不读 bashrc。

需要 stdin 数据的脚本不要同时通过 `bash -s` 从 stdin 读取源码，先落盘再执行。正在运行的脚本不得原地编辑；需迭代时先停止，或运行包含依赖与目录上下文的独立版本。

解析外部命令输出优先用结构化格式；只能解析文本时显式固定适用的 locale，并测试解析失败。

## 3. 进程与超时

脚本负责子进程、服务停止、超时或信号时，读 `playbooks/references/shell-processes.md`。仅生成短命令无需加载进程管理细则。

## 4. 远端 / CI 脚本的本地沙盘

失败代价高、仅由 CI/部署/定时器运行的脚本，应有本地可运行的隔离测试：

- 外部 CLI 用命令桩，覆盖真实输出与非零退出；副作用落临时目录，Git 操作使用临时仓库。
- 断言实际 argv、文件、ref 与状态变化，不能只断言成功日志。
- 生成 JSON/YAML/unit 等文件时用实际解析器或等价结构校验验证生成物。
- 按触发路径、失败与恢复分支覆盖，不只跑 happy path。
- 测试需要 source 生产脚本时，先确保主流程隔离；source 守卫不得退出调用方，且直接执行不能因测试开关而静默跳过。脚本自身路径按实际解释器机制解析，不将调用方路径误作自身。
