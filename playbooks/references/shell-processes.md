# Shell 进程管理与退出

仅在脚本负责后台任务、子进程、停止或超时时读取。

## 任务边界

优先由已知 PID、进程组或服务管理器标识任务。使用 pgrep/pkill 的命令行模式前，检查模式是否会命中调用 shell 或无关进程；正则不是字面匹配。不能用宽泛进程名代替归属核验。

wrapper 退出不等于孙进程退出。需要“整个任务已停止”的保证时，定义进程组/cgroup 等资源边界，并验证所有成员已退出；只检查 kill 或 timeout 的返回码不够。

## 超时和信号

为任务设置有界等待和最终强制终止路径。timeout 的信号及 kill-after 行为应按实际实现核实；不要因有一个超时参数就声称整棵任务已回收。

后台启动可能继承与终端不同的信号处理。需要优雅关闭时明确 SIGTERM/取消协议，保证阻塞等待可唤醒；不要只依赖 KeyboardInterrupt。由框架管理生命周期时，使用其关闭钩子，不随意覆盖处理器。强制终止不能保证应用清理执行。

## 验收

在沙盘通过真实启动方式运行，等待就绪后发信号；检查正常停止、超时、拒绝退出及子进程清理。所有等待有上限，失败路径也回收测试进程。定时器的外层截止时间应给内部告警和清理留余量。
