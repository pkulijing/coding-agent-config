# LLM 编排与运行中指令

仅在多步工具调用、一次性任务拆分或修改运行中 Agent 指令时读取对应小节。

## 多步调用与一次性清单

先定义执行协议：系统是否把工具结果返回模型继续决策？

- 多步 Agent：逐轮处理工具调用与结果，明确终止、失败、权限和总预算。
- 一次性拆分：让输出结构直接表达完整步骤清单及依赖，不假设一次 tool_call 返回天然包含所有后续步骤。
- 两类都应验证用户请求与实际执行范围一致；“列出的步骤都成功”不能证明没有漏步。
- 工具 schema 作为能力真源，prompt 不手写容易漂移的工具数量和重复清单。确需两份表达时检查一致性；fake 只能验证程序对给定返回值的处理。

具体协议消息格式查供应商当前文档，旧模型的成功率不能作为其他模型的保证。

## 修改运行中 Agent 指令

区分磁盘定义、运行时加载配置和目标会话实际使用版本。先查框架原生加载/缓存机制，再选择重新加载、新建或迁移；不要擅自删除会话历史。

通过实际请求路径或会话检查能力取得版本、哈希或脱敏匹配证据；文件哈希和重启成功不能单独证明会话生效。无法查看时明确未核实。

按产品协议进行一次能区分新旧行为的实际交互验收，例如派工、回交和汇总；只说“会遵守”不算验收。公开产物只留必要脱敏结果，不复制私密提示词或会话原文。
