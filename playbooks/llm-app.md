# LLM 应用开发规则

接入或修改 LLM API 调用时读本文。它不要求为每次文本调用建立评测工程。

## 接入契约

- 优先使用供应商支持的 SDK。先依据用户提供的 endpoint 与官方文档确认协议、模型、凭据来源和可用参数；兼容 API 不等于所有模型默认值一致。
- 明确超时、重试与总耗时预算。需要控制 thinking/reasoning、输出结构或供应商扩展参数时，查当前模型与 SDK 文档，不沿用其他模型的默认值。
- 使用任务实际输入规模验证集成；小输入跑通仅证明该次请求完成。仅在产品使用流式、或排查延迟时增加流式探针，区分首块、正文、结束与错误。
- 不把 HTTP 成功或 SDK 无异常等同于任务完成；检查返回内容、结构、工具执行结果及中断状态。
- 代码测试覆盖解析、错误处理和编排；mock 不证明模型会按预期回答。模型效果验证按该产品交付要求决定，不默认要求统计基准、多模型或重复运行。

## 按场景加载

- 多步工具 Agent、一次性任务拆分，或更新运行中 Agent 的指令：读 `playbooks/references/llm-orchestration.md` 的对应小节。
- SDK 的具体参数和协议使用当前官方文档，不在共享规则长期保存供应商配方。
