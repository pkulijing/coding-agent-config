# 设计讨论隔离与单提交归档

## 开发项背景

#176 与 #181 指向同一条设计讨论工作流：`/design` 直接在当前分支写文档，每次存档又新增提交，导致主工作树受污染、同主题中间快照堆积，交错其他开发提交后难以安全整理。

## 实现方案

- 每个主题默认使用项目 `.worktrees/` 下的独立分支和工作树；新建、续聊及无参数列举都检查各工作树和本地/远端分支，以主题路径和实际内容恢复归属，不引入 SHA 索引文件。
- 首次归档创建主题提交，后续持续 amend 归属明确、未发布、未集成且未共享的同主题 HEAD。`Design-Topic` trailer 辅助定位；提交前核对完整 index 与允许文件，保留实际执行 Agent 的署名。
- 交错、混合范围或已发布历史先核对影响和授权；旧线性历史在临时分支整理，验证最终 tree、其他补丁和提交说明。缺少授权时保全最新文档并报告待处理，不追加临时快照。
- 讨论中保留主题分支；定稿或搁置后按备份、rebase、FF 合入和清理条件收尾。远端替换使用明确 SHA 的 lease，主树脏区和未保全资产阻止相应操作。
- 更新 design、commit 协作契约、全局宪法和 README；Git 细则集中在 `skills/design/references/git-lifecycle.md`，主技能按阶段要求读取。

验证产物为本目录 `test-design-git.sh`、`VALIDATION.md` 和 `REVIEW.md`。九组本地 Git 沙盘覆盖主树三类脏区、主题交替与恢复、index 夹带、发布历史和 lease、窄 fetch 映射、交错提交整理、FF 合入及冲突保全。语法、技能结构校验通过，完成两轮重档五角度独立 review，无高置信遗留问题。

## 局限性

- 本轮交付自然语言技能及其 Git 操作验证，没有生产级历史整理执行器；沙盘不能证明任意 Coding Agent 都会正确执行全部指令。
- 复杂混合提交、共享引用和已集成主题重开仍需具体历史方案及授权，不承诺任意拓扑自动收敛。
- 未在真实远端制造强推场景；未完成 CC 真实会话端到端验证。

## 可沉淀项

主题隔离与单提交归档已直接沉淀到共享 design/commit 技能。窄 fetch refspec 下不能把 remote-tracking 空结果当作远端不存在的经验，已纳入本轮细则和沙盘。暂无需要另建 issue 的跨项目候选；当前仓库即 coding-agent-config，不向自身自动提 issue。
