## 方案

### 1. 每个主题独立隔离，恢复依据来自 Git

- 新主题默认从核实的主分支基线建立 `.worktrees/design-<ascii短名>/` 与 `codex/design-<ascii短名>` 分支，不占 round 编号。中文主题路径仍为 `docs/design/<主题>/`。
- 新建前及 `--resume` 时，联合检查 `git worktree list --porcelain`、本地和已 fetch 的远端主题分支、主分支主题路径及路径历史。以实际文档路径和提交内容核实归属，分支名仅用于候选定位。
- 唯一匹配时复用既有工作树；分支存在但工作树缺失时恢复工作树；只有远端主题分支时取回并恢复。匹配多个、路径重名或工作树存在无关改动时明确停止相关写操作，说明具体冲突。
- 从主 checkout、开发 worktree 内调用都允许定位到兄弟 design 工作树，不在当前开发工作树写设计文件，不创建嵌套 worktree。所有调用显式锚定绝对路径。
- 主树的脏区与暂存区不 stash、不 reset、不携带到 design 分支；已存在于主树的未提交主题文档仅在明确核对迁移范围后处理，不把无关内容一起搬走。

### 2. 同主题单提交归档

- 在 Git 提交 message 中使用稳定的主题路径 trailer（例如 `Design-Topic: docs/design/<主题>`），辅以实际变更路径核验；不保存易漂移的 SHA 索引。
- 首次存档创建一个提交；后续只暂存本主题的 `DISCUSSION.md`、`DESIGN.md` 和获授权资产，核验整个 index 无其他内容，再 amend 已确认属于本主题的 HEAD。
- 提交前仍执行 `/commit` 的 review、lint 与真实 Agent 署名规则；design 专用入口只改变提交定位、范围和创建/amend 选择，不把通用 `/commit` 改成默认 amend。
- 非 HEAD、多个旧设计提交或混合提交不直接 amend。先列目标提交、其他提交、推送状态和被其他分支/worktree 引用情况，打备份 tag，再生成可审阅的整理方案。已确认可整理的未发布线性历史，在临时分支重放其他提交并把本主题最终文档收敛为一个提交；核对最终文件树、其他提交说明与补丁均保留后才更新目标分支。
- 混合提交、合并拓扑、冲突、共享祖先或归属不明的情况停止自动整理，保全文件并要求针对具体方案确认。本轮不承诺任意历史都能自动收敛。
- 已定稿或搁置并已合入主分支的主题重开，须先报告改写已集成历史的代价并确定策略，不能默认改写主分支或悄悄新建第二个同主题提交。

### 3. 存档、同步、合入与清理

- 讨论中存档：只更新主题分支归档提交，保留工作树；不在每轮结束时合入主分支，避免下一轮 amend 必须追溯改写主线。
- 跨设备同步使用专用主题分支。任何已发布提交在本地改写前，先说明 SHA 与后继链影响及远端同步方案；取得对应授权后才改写。需要替换远端时只允许针对已核验远端 SHA 的 lease 更新，明确禁止无条件 force。
- 没有改写授权或无法核实远端状态时，保留主题工作树中的更新，明确报告尚未提交/同步；不靠追加临时快照规避单提交要求，不把本地存档宣称为跨设备可用。
- 定稿或搁置：先完成最终归档，再核对主分支清洁度和分叉情况，必要时备份并 rebase 主题分支，然后 FF 合入。主 checkout 有无关改动或出现冲突时保留主题分支与工作树，等待处理。
- 清理前核验最终主题提交已在目标分支可达、主题文件一致、工作树与 index 干净、没有未保全资产，随后按明确清理授权移除工作树和主题分支；不自动推主分支、不删除备份或远端分支。

## 外部行为实证

2026-11-02 已在临时 Git 沙盘执行，未操作本仓历史或真实远端。复现脚本本轮执行时位于 `/tmp/design-archive-spike.sh`；以下步骤供重新建立沙盘时复现，不依赖临时目录长期存在：

1. 创建本地 bare origin 和 main 基础提交；创建 design/topic 并提交 `docs/design/topic/DESIGN.md` 的 v1，push 到本地 origin。
2. 写入 v2，定向 add 后运行 `git commit --amend --no-edit`；对比前后 SHA，并运行 `git rev-list --count main..HEAD`。
3. 再执行普通 `git push origin design/topic`，检查退出码非零。
4. 切回 main，修改无关已跟踪文件，记录 `git status --porcelain`；运行 `git worktree add <临时主题路径> design/topic`，分别检查主树状态与新树状态。

结果：amend 前后 SHA 不同，主题提交数仍为 1；普通 push 被拒绝；从含无关改动的 main 建立主题工作树后，main 状态逐字不变，新树干净。故独立工作树可解决隔离问题，但无法消除已发布提交的历史改写与同步成本。

## 验证计划

指令文件改动以场景推演和真实 Git 沙盘核验行为；不以关键词存在充当验收。确认计划后先落场景断言，再完成规则修改。测试全部使用临时仓库、临时 HOME、本地 bare 远端、固定身份/时钟/locale、禁用用户 Git 配置与 hooks，不访问真实网络。

| 输入场景 | 必须得到的结果 |
| --- | --- |
| 干净主树开启新主题 | 主题只在独立树出现，主树与 index 不变 |
| 主树有已暂存、未暂存及未跟踪无关内容 | 启动、续聊、存档均不改变它们 |
| 首次归档后多次续聊、定稿或搁置 | 同主题只有一个归档提交，文件为最新版本 |
| 两主题交替 | 两个 worktree 各自更新，不交叉提交 |
| worktree 已移除但分支存在；仅远端分支存在 | 恢复原主题，不新建第二份 |
| HEAD 是其他开发提交；旧主题多提交交错 | 不误 amend；整理后最终树等价，其他补丁与说明保留 |
| index 混入其他主题；旧提交混合范围 | 归档前阻断，其他内容原样保留 |
| 已 push 的主题更新，无改写授权 | 不改写提交、不强推、不声称已同步，文件保全 |
| 已获针对性授权但远端又发生变化 | lease 拒绝覆盖新远端，现场可恢复 |
| 主线前进后定稿；主树脏区；合入冲突 | 成功路径最终只合入一个主题提交；阻塞路径保留 worktree/分支/文档 |
| 其他分支/worktree 引用旧提交；已合入主题重开 | 明确受影响引用与授权边界，不静默移动其他 ref 或改写主线 |

修改完成后运行 Markdown 格式检查、`git diff --check`、场景沙盘验证及当前仓库适用门禁；提交前按 `/review-loop` 在独立 context 审查指令一致性、历史安全与验收覆盖，修复后再提交。
