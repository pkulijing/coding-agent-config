# 设计讨论隔离与单提交归档

> 来自 [#176 /design 讨论期间应持续 amend 同一提交，避免累积中间快照](https://github.com/pkulijing/coding-agent-config/issues/176)
> Labels: `type:bug` `area:skill` `priority:P2`
>
> 来自 [#181 /design 默认使用独立 worktree，避免设计文档污染主工作树](https://github.com/pkulijing/coding-agent-config/issues/181)
> Labels: `type:bug` `area:skill` `priority:P1`
>
> 用户启动指令：`/start #176 #181`

## 背景

当前 `/design` 要求直接在当前分支更新 `docs/design/<主题>/DISCUSSION.md` 与 `DESIGN.md`，显式排除 worktree；每次会话结束、定稿或搁置时又调用通用 `/commit` 新建提交。同一主题因此会污染主工作树并累积中间快照，交错其他主题或开发提交后更难整理。

#176 的实际案例中，同一主题产生了 6 个设计提交，期间穿插其他开发项的 3 个提交。用户要求讨论期间始终维护该主题一个逻辑提交，并要求 design 也使用独立 worktree。

## 需求

1. 新主题默认在项目 `.worktrees/` 中建立独立分支与工作树；同主题续聊优先识别、复用或恢复已有隔离环境，不重复创建主题文档。
2. 首次归档创建一个主题提交，继续讨论、跨会话续聊、定稿和搁置持续修订该逻辑提交，不追加同主题中间提交。
3. 主题与提交的关联可由仓库事实恢复，不依赖会话记忆，不引入会与 Git 漂移的本地索引文件。
4. 暂存与提交范围只包含本主题两份设计文档及获授权的 assets；不得纳入其他主题、开发项或主工作树改动。
5. HEAD 属于其他工作时禁止直接 amend。历史整理须保留其他提交的补丁和说明，覆盖已有多个设计提交、未提交文件、其他分支或 worktree 引用旧历史等情况。
6. 明确已推送历史的改写与同步授权边界，不暗中 force-push；无法安全自动归档时保全文件并说明阻塞点。
7. 明确讨论中存档、定稿、搁置的合入与清理流程，文档未保全不得删除工作树。
8. 同步全局宪法和当前工作流说明；CC / Codex 两端一致，提交使用实际执行 Agent 的署名，描述当前方案。

## 验收

- 从干净或含无关改动的主工作树启动设计，主题文档只写入独立工作树；主工作树原有内容和暂存区保持原样。
- 多轮讨论及 `--resume`、定稿、搁置后，同一主题仍只有一个逻辑归档提交，文档反映最新进度。
- 两主题交替或穿插开发提交，互不覆盖、互不夹带；整理旧碎片提交后文件树等价，其他开发补丁和提交说明保留。
- 跨会话能找到主题所在工作树、分支与归档提交，不因主树看不到文件而另起同名主题。
- 已推送历史未经相应授权不改写、不强推；状态不明确时保全现场。
- 各种结束状态均有明确存档、合入与清理规则。

## 范围与约束

修改设计 skill、必要的 commit 协作说明、全局宪法及现行入口说明，并补充可复现的 Git 沙盘验证。保留 design 不写业务代码、不拆 issue、不占开发轮次、不改 DEVTREE、不写 SUMMARY 的边界。

本轮是修订 design 工作流的开发轮，遵循 `/start` → 执行 → `/finish`；不是一次 design 讨论。本轮不自动批量整理其他项目的历史，不实现 #172 的开发轮压缩功能，不批量改写历史 docs。
