# 正式开发先规划审批，轻量开发自主执行

> 读者：使用与维护开发技能的人 · 何时审计划，去哪里找批准版
> 来源：本轮对话批准的实施计划

## 目标

正式开发先在客户端原生 Plan 模式调查和讨论，批准后在仓库永久保存一份计划。小改供人和自动化直接调用。

## 关键决策

- 调查真实入口、已有行为与测试。计划以现状、改法、取舍和验收的摘要开头，后附完整提纲。已批准的方案直接沿用。
- 只讨论时留在聊天里，退役独立设计入口。批准后才建工作树、落计划。保全历史文档，兼容在途旧轮次。
- 调用轻量入口即授权小改。超范围交回调用方，可跳过或报告。当前客户端已开启的原生模式仍然有效。

## 实施提纲

同步全局规则、正式与轻量入口、收尾提交、新项目初始化及文档检查。安装迁移只清理本仓管理的旧技能链接。按起始基线独立审查，提交、本地合入并核验部署。

## 验收

- 批准前只调查，退回则继续规划，批准一次后实施。正式轮次只留 PLAN.md。
- 无人交互运行轻量小改，检查测试、review、提交与超范围返回。
- 测试新旧文档、缺失计划、多余文档、显式文件与全库扫描，以及安装幂等和第三方同名技能保全。
