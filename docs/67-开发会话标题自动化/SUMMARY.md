# 开发会话标题自动化

## 背景与方案

用户通过桌面 App 和手机远程开发，希望会话列表显示开发轮次及完成状态。新增 `scripts/codex_session_title.py`，使用 uv 独立脚本声明 Python ≥3.11 与 `websockets==15.0.1`；复用正在运行的 App Server，通过 Unix socket 上的 WebSocket 协议更新真实会话标题。

`/start` 在计划确认并开始实施时设置 `r<N>-<中文描述>`；`/finish` 在适用的提交、收尾成功后设置 `r<N>-<中文描述>-已完成`。轮次和描述由技能按本轮开发文档传入，会话 ID 使用 `CODEX_THREAD_ID`。非 Codex 环境不调用；失败报告实际状态，不撤销开发成果。

## 实现

- 从 `codex app-server daemon version` 的 JSON 发现现有服务，也支持显式 `--socket`；不启动、重启或升级服务，不开放端口，不写数据库。
- 初始化后用 `thread/read` 核对当前会话 ID 与 `name` 字段，再调用 `thread/name/set`，最后读回验证；返回相同标题时不再写入。
- 正确处理通知和请求 ID；参数错误、服务发现失败、协议错误及超时有非零结果。写入后失联或无法读回时报告 `unknown`，不将零退出码或成功回执单独当成业务成功。
- 操作设置总超时，服务发现使用独立进程组，取消时结束本次组内进程并回收直接子进程；即使包装器先退出、后代仍持有管道，也不继续等待。WebSocket 关闭等待限制为 0.1 秒。uv 准备 Python / 依赖的时间不在脚本操作超时内。
- 更新 README 的标题约定、依赖与部署说明；既有技能和脚本目录使用主 checkout 软链，不需要新增 skill 注册或改原生配置。

## 验证

- 主入口隔离测试先红：生产脚本不存在时 happy-path 用例失败；实现后测试通过。补充包装器后代持管道的沙盘后，回归测试在旧实现上再次变红（0.2 秒预算实际等待约 3.1 秒）；修复进程组清理后通过。
- 测试通过本地 Unix WebSocket fixture 和隔离 HOME / PATH / CLI 执行真实主入口，覆盖普通改名、完成后缀幂等、中文及特殊字符、参数边界、缺失会话 ID、服务发现异常、RPC 错误、错会话、无效响应、读回不一致、写后失联与超时回收。
- 最终 32 项测试通过，新增 Python 文件的 ruff 检查及两份技能的结构、共享路径引用检查通过。开发树按用户确认归入“开发项收尾”。
- 两轮重档独立 review 均完成五角度检查，最终无高置信 correctness finding，详见 REVIEW.md；最终代码再次调用真实服务返回 `verified`、`changed=false`。
- 本机 CLI `0.167.1`、运行中服务 `0.169.0`：真实当前会话改为 `r67-开发会话标题自动化`，原生接口读回一致；再次执行返回 `changed=false`。
- 用户确认已在客户端看到新标题；未分别记录桌面与手机各自的检查结果。

## 局限与后续 TODO

- 当前实现需要 Unix socket；只在本机 Linux 服务实测，不由此推断 Windows 或其他部署支持。不同部署须显式给出已知 socket，或在发现失败时报告前提缺口。
- 同一会话同时执行不同开发轮次时，标题沿原生接口遵循后写生效；工具不会用会话标题替代开发文档真源。
- 用户已确认开始标题可见；完成标题在本轮真正收尾时再验证，不提前标记完成。
- 当前成果仍在本轮工作树中；未合入主 checkout、未推送。通过目录软链部署的日常入口在合入主 checkout 后才更新。
