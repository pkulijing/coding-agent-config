# 0001 文档产出闭集：只留规格与决策，不再留过程

> 读者：想往 `docs/` 里再加一种文档的人 · 为什么这里是闭集
> 状态：已接受（2026-11-19）

## 背景

到第 69 轮为止，`docs/` 累积 68 个轮次目录、231 个 Markdown、18,967 行，约 275 行/轮。其中 28 个轮次在仓库内零引用；被引用最多的是 `docs/11`（46 次），引用来自代码注释指向"当初为什么这么设计"，属于决策理由，不是过程记录。

三件套（PROMPT / PLAN / SUMMARY）是 2026 年初为窄上下文模型设计的外置工作记忆：需求写下来喂给模型、计划先输出供人审、总结留档防遗忘。这三件事后来分别被对话上下文、模型自主规划、issue 与 commit body 覆盖，剩下的读者只有作者本人和 `/devtree`，而 `/devtree` 的产出同样无人阅读。作者已不再读计划与总结，只为它们付写作和审查成本。

同时，产出没有边界：模型自发增补 `deployment` / `verification` 一类文档，因为指令里到处是"记录""留痕"，却没有一条说"什么情况下不要写"。

## 决策

1. 一轮的产出闭集：issue、一份 ≤15 行的轮次记录 `docs/<N>-<中文描述>.md`、可选 ADR `docs/adr/<NNNN>-<slug>.md`、commit body、代码与测试。不再产出 PROMPT / PLAN / SUMMARY / REVIEW 流水 / VALIDATION / deployment / verification。
2. 新文档出生时必须有 `> 读者：<谁> · <什么问题>` 一行。答不出的内容写进 commit body，不落盘。
3. `docs/DEVTREE.md` 冻结于第 69 轮，`/finish` 不再更新；`/devtree` 保留仅供存量修复，`/bootstrap` 不再生成新开发树。
4. `/design` 收成单文件 `docs/design/<主题>.md`，直接在主 checkout 提交；不再有独立工作树、主题分支与归档提交协议。
5. 存量 68 个轮次目录保持原样，不迁移、不改写。
6. 收尾与开轮的必写项收敛为「轮次记录 + 可选 ADR」；`routine-slim` 可在技能内收缩这类文档仪式，与宪法冲突的只报告，宪法仍由人改。

## 后果

- 好：每轮文档从 4–6 份 / 275 行降到 0–1 份 / ≤15 行；`/finish` 少两步；审查面回到代码与规则本身。
- 代价：过程细节只留在对话与 commit body，跨会话回溯要靠 `git log` 和 issue；长讨论仍需要一份 DESIGN；历史 68 轮的内容不再有索引，只能按目录名找。
- 推翻条件：出现必须由人逐轮审计的合规要求，或模型再次失去长上下文与自主规划能力。推翻时新写一份 ADR 取代本份，不改本份。
