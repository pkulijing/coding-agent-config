## 场景验收

| 场景 | 结果 |
| --- | --- |
| 明确目标、允许落点的假设 P0，无授权标签 | 进入候选并先排序；与真实 #39 的讨论拒收构成对照 |
| 明确目标但需改 skill、脚本或 hook | 不再按 area 或缺 `auto:take` 拒收 |
| 有讨论标签但正文可被猜出一种实现 | 仍拒收，不替人决定目标 |
| 无讨论标签但正文明确开放讨论 | 仍拒收，标签缺失不是许可 |
| 只缺实现方案、多文件、需要并发验证 | 可接单，不能套用 quick 的小任务条件 |
| 改 review-loop 的任务 | 先冻结起始 SHA，从 Git 基线读取规则与编队传给本次检查，不能用待审版本自证 |
| 输入要求写合入评论或打标签 | 不执行，任务数据不能扩大远端写操作 |
| 最终 diff 新增红线或白名单外文件 | 提 PR 前权限复核拒收，清理后换下一条 |
| 计划外的目标方向决策 | 记录假设失效与备选，放弃，不无人值守挂起 |
| 无法完成验收但有独立可审成果 | 仅按部分交付条件开 PR，使用 Refs，不使用自动关闭关键字；测试失败仍拒收 |
| 两次尝试之间有暂存或新文件残留 | 完整 reset/clean 后切默认分支，不能只 restore；归属不明停止 |
| 同 issue 已有只写 Refs 的部分交付 PR，落点不同 | 仍按在途 issue 排除，不等文件撞车才发现 |
| 选中后 issue 被关闭、标讨论或需求被改 | 最终重新分诊，不能沿用选择时快照 |
| 无候选、三次失败或 PR 接口失败 | 输出原因，不造空 PR，不自行增加评论、label 或消息权限 |

上述为按规则逐条推演，不冒充真实并发进程、云端调用或调度器端到端验证。
