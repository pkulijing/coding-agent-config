# 收尾提交原则与询问精简

## 开发项背景

#190 要求减少收尾过程中的碎片化状态提交与重复人工提醒；#186 要求移除 finish 每轮固定的“刻意不做”扫描和归档询问。用户在同轮追加明确偏好：finish 默认清理工作树、分支与备份，仅在主动要求保留时跳过。

## 实现方案

- commit 以可独立审阅、回退和说明目的的交付单元组织提交。同一次连续收尾先汇齐 SUMMARY、开发树和适用 README，避免把收到授权、准备合入等过程状态逐个提交；独立功能、修复、部署验收和影响判断的新事实仍可独立记录。
- finish 删除原 Step 2 的固定归档流程，连续调整步骤与跨技能引用。手动 `wontfix` 归档能力保留，旧 BACKLOG 迁移继续保全原因与信息，不引用已删除步骤。
- 调用 finish 默认清理本轮 worktree、本地开发分支与本轮 backup tag，不再确认是否清理。“不要清理”或 `--no-cleanup` 保留三者；局部保留要求优先，保留 worktree 时保留其正在使用的分支。
- `--no-merge` / `--keep-branch` 默认仅清理已保全成果的工作树，分支与备份保留；可与 `--no-cleanup` 组合。合入与 push 仍核对各自授权，已有明确授权在原范围内持续有效。
- 清理前核对成果、未跟踪/忽略资产与对象归属；失败不强删，不越过产品对托管工作树的保护，不删除其它工作、发布 tag 或远端引用。交付说明区分提交、本地合入、推送和部署，并核对 rebase 前后补丁。
- README 与全局入口同步默认行为；review 的编队、角度、模型、门槛及历史保护保持。
